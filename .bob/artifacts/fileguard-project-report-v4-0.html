Abstract

FileGuard is a browser-based file integrity verification tool built with Python and Streamlit. It computes the SHA-256 cryptographic hash of any uploaded file, allows the user to record that hash as a trusted reference, and compares a file's current hash against the reference at any later time to determine whether the file has been changed.

The application runs entirely on the user's local machine. No file content, hash, or metadata is transmitted to any external server. Files are never written to disk and are never executed.

Key capabilities include SHA-256 hash computation, original reference recording, structured JSON export and import for cross-session verification, side-by-side hash comparison, colour-coded pass/fail verdicts, and a downloadable plain-text verification report.

1. Introduction

1.1 Background

Digital files are the primary medium through which information is created, shared, and stored. A document, a software installer, a database export, or a configuration file may pass through email servers, cloud storage platforms, USB drives, and network file shares before reaching its intended recipient. At every step, the file is vulnerable to unintended or malicious modification.

Traditional antivirus software detects known malware signatures, but it does not answer a simpler, equally important question: "Is this the exact file I originally had?" Cryptographic hash functions provide a mathematically precise answer to that question.

1.2 Motivation

A first-year engineering or cybersecurity student typically learns about SHA-256 from textbooks but has no accessible tool to interact with it hands-on without using a terminal command. FileGuard was developed to bridge that gap.

2. Problem Statement

Files shared over networks, stored in cloud drives, or passed between systems are vulnerable to silent modification. Causes include:

  • Transmission errors during network transfer or storage media degradation.
  • Software bugs in editors, converters, or synchronisation tools.
  • Deliberate tampering by an attacker who has access to the file at any point in its journey.

Existing tools fall into two categories: command-line utilities (inaccessible to beginners) and enterprise FIM tools (too complex). There is no lightweight, beginner-friendly, browser-based tool that covers the complete workflow.

3. Objectives

  1. Compute the SHA-256 hash of any uploaded file locally, without transmitting file contents to any server.
  2. Allow the user to record a computed hash as a trusted original reference with a UTC timestamp.
  3. Export the recorded reference as a structured JSON file for future sessions.
  4. Import a previously exported JSON record and validate its structure and SHA-256 format.
  5. Compare the current hash of a file against the active reference and display a clear verdict.
  6. Show both hashes side-by-side in selectable text areas.
  7. Generate a downloadable plain-text verification report.
  8. Explain the meaning and limitations of hash-based verification in plain language.
  9. Enforce safety controls: size limits, no file execution, no permanent storage.

4. Scope of the Project

In Scope

  • SHA-256 hash computation for any file up to 10 MB.
  • Recording a reference hash in the current browser session.
  • Exporting and importing a structured JSON verification record.
  • Comparing a file's current hash against a reference hash.
  • Running entirely on the user's local machine with no network communication.

Out of Scope

  • Antivirus scanning or malware detection.
  • Permanent storage of files, hashes, or user data.
  • Multi-user or networked deployment.
  • Automated or scheduled integrity monitoring.

5. Existing Approach and Proposed Solution

5.1 Existing Approach

# Linux / macOS
sha256sum report.pdf

# Windows
certutil -hashfile report.pdf SHA256

This approach requires terminal knowledge, manual copying, and visual string comparison — a barrier for beginners.

5.2 Proposed Solution

  1. Step 1: Upload a file, see the hash, click one button to record it.
  2. Export: Download the reference as a JSON file for safe keeping.
  3. Step 2: Upload the file again (or load the saved record), see both hashes side-by-side, receive an immediate verdict.

9. SHA-256 Hashing Explanation

9.1 Key Properties

  • Deterministic — same bytes always produce the same hash.
  • Avalanche effect — a single bit change produces a completely different hash.
  • Pre-image resistance — a hash cannot be reversed to recover the original file.
  • Collision resistance — computationally infeasible to find two files with the same hash.

9.2 How FileGuard Uses SHA-256

def compute_sha256(file_bytes: bytes) -> str:
    h = hashlib.sha256()
    stream = io.BytesIO(file_bytes)
    while chunk := stream.read(65536):   # 64 KB chunks
        h.update(chunk)
    return h.hexdigest()

9.3 Avalanche Effect Example

Input: "Hello, World!"
SHA-256: dffd6021bb2bd5b0af676290809ec3a53191dd81c7f70a4b28688a362182986f

Input: "Hello, World?"  (only last character changed)
SHA-256: f16c3bb0532537acd5b2e418f2b1235b29181e35cffee7cc29d84de4a1d62e4d
Important: A hash match confirms byte-for-byte identity only — not that the file is free of malware. FileGuard is not an antivirus tool.

13. Results and Discussion

All nine objectives stated in Section 3 have been implemented in the current version of app.py. The automated self-test suite confirms 70/70 tests pass. Design outcomes include selectable hash text areas, character-level hash diff, a live sidebar dashboard, and a visual step-progress tracker that updates as the session advances.

14. Advantages

  1. No installation complexity. Starts with a single command after installing Python and Streamlit.
  2. No external dependencies beyond Streamlit. All cryptographic logic uses Python's standard library.
  3. Completely local. No data ever leaves the user's machine.
  4. Files are never executed. Reads only raw bytes.
  5. Cross-session verification. JSON export/import allows verification weeks later.
  6. Honest about limitations. Explicitly states what SHA-256 does and does not prove.
  7. Educational value. SHA-256 explainer and character-level diff teach hashing interactively.
  8. Accessible to beginners. Two numbered steps; no terminal knowledge required.

15. Limitations

  1. Single file per session. Only one reference hash at a time.
  2. Session volatility. Reference lost on browser refresh if JSON was not exported.
  3. No pytest or CI pipeline. Self-test suite must be run manually with python app.py.
  4. 10 MB file size limit. Large files cannot be verified.
  5. SHA-256 only. MD5, SHA-1, SHA-512 not supported.
  6. No digital signature on JSON record. An attacker who can modify both file and record defeats the check.
  7. No verification history. Each session starts fresh.

17. Conclusion

FileGuard demonstrates a practical application of cryptographic hashing to the real-world problem of file integrity verification. By wrapping Python's hashlib.sha256() in a Streamlit interface, the project makes a professional-grade security technique accessible to users with no terminal or cryptography background.

The codebase is intentionally minimal — four files, one external dependency — making it straightforward to understand, extend, and audit. The safety controls reflect sound principles: no file execution, no data transmission, enforced input limits, structured validation, and careful honesty about what the tool can and cannot guarantee.

This project demonstrates competence in Python programming, web application development with Streamlit, cryptographic concepts, input validation, session management, JSON data exchange, and security-aware software design.
